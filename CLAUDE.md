# Project Overview
Build a simple, functional Equity Risk Dashboard inspired by tools used on institutional equity trading desks.

The goal is to create a resume-quality project that demonstrates practical equity risk management and financial analysis skills.

# Core Principles
- Simplicity first. Build only essential features that provide meaningful functionality.
- Prioritize working functionality and financial accuracy over visual polish.
- Avoid overengineering, unnecessary abstractions, and complex infrastructure.
- Use the simplest reasonable technology stack and architecture.
- Do not add features, dependencies, or complexity unless they provide clear value.
- Prefer a small, fully functional application over a large, incomplete one.

# Financial Accuracy
- Use established financial formulas and clearly document assumptions.
- Separate financial calculations from the user interface.
- Use reliable market data and handle missing or invalid data appropriately.
- Clearly distinguish historical estimates from forecasts or predictions.
- Write unit tests for financial calculations and important edge cases.
- Never display placeholder or fabricated financial data as real results.

# Development Workflow
- Plan major features or architectural changes before implementation.
- Break development into small, manageable phases.
- Implement one feature at a time and verify it works before moving on.
- Follow the existing project structure and reuse code where appropriate.
- Keep code readable, maintainable, and straightforward.
- Avoid changing unrelated files.
- Run relevant tests and fix failures before marking work complete.
- Never commit, push, or deploy without explicit permission.
- Never hardcode or commit API keys, credentials, or secrets.

# UI/UX
- Use a clean, simple, professional financial dashboard design.
- Prioritize clarity and usability over animations and visual effects.
- Display financial metrics with appropriate units, percentages, and labels.
- Avoid unnecessary pages, charts, widgets, and decorative components.

# Communication
- Explain important technical decisions and financial calculations in simple terms.
- Keep explanations concise and practical.
- Recommend the simplest viable approach when multiple solutions exist.
- Flag significant trade-offs or unclear requirements.
- After completing a feature, summarize what changed, what was tested, and what comes next.
